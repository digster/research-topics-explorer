# 2026-04-23

## Feature: Disciplines tab — thematic groupings across v5/v6/v7

### Problem
The app had five views (Graph, Roadmap, Cards, Hubs, Creators) but no way to see topics clustered by **thematic discipline**. A screenshot reference showed a multi-column layout with "Phase 1: The Meta-Frameworks", "Phase 2: Structure & Connection", "Phase 3: Mind & Perception" — each listing numbered topics belonging to that thematic cluster.

### Discovery
The v5 source markdown (`research-topics-v5.md`, lines 401–563) already defined the exact 10-phase thematic sequence shown in the screenshot — the screenshot was rendering v5's editorial scheme. This meant the new page could **ratify the existing v5 curation** rather than invent a new taxonomy. v6 topics carry a `Likely v5 Phase` field in their master table; v7 topics map to phases thematically by group (creators, texts, crafts, disciplines, emerging).

### Design decisions (confirmed with user via AskUserQuestion)
1. **Source of groupings**: new `disciplines.md` parsed by `parse.mjs` → emitted into `data.js`. Keeps curation in plaintext, mirrors the existing v5/v6/v7 markdown pipeline.
2. **Topic scope**: all three versions (v5 + v6 + v7), each row tagged with a version badge.
3. **Tab label**: "Disciplines".

### Files changed
1. **`disciplines.md`** (new) — 10 phase sections anchored on v5's Phase 1–10 names. Each section has an optional subtitle paragraph + a `### Topics` bulleted list. All 162 topics from v5 (56) + v6 (35) + v7 (71) are placed into exactly one phase.
2. **`parse.mjs`** — added `parseDisciplines(md, index)` that reads level-2 `## Phase N: Name` headings, extracts subtitle + bullet list under `### Topics`, and resolves every topic name through the existing `resolveConnection` fuzzy index (same resolver used for `Connects to:` lines). Missing `disciplines.md` is tolerated (ENOENT is swallowed). Console report now includes `disciplines: N (unresolved discipline topics: M)` and surfaces unresolved names so curators can fix typos.
3. **`index.html`**:
   - Added `Disciplines` tab button between Hubs and Creators (line 509).
   - Added `<div id="disciplines" class="view">` container (line 556).
   - Added a CSS block for `.disciplines-grid`, `.discipline-col`, `.discipline-topic` scoped under `#disciplines` (line 419). Uses `repeat(auto-fit, minmax(320px, 1fr))` so the grid reflows from 4 columns at 1600px down to 1 column at narrow widths.
   - Added `renderDisciplines()` which reads `DATA.disciplines`, sorts by phase number, renders columns with phase tag + title + subtitle + numbered topic rows. Each row shows topic name + version badge. Clicks call `selectTopic(id)` so the existing panel populates for free. Rows filtered out by `visibleTopics()` disappear; columns that end up empty show a "No topics match current filters" placeholder.
   - Added the dispatcher case `case "disciplines": renderDisciplines(); break;`.
4. **`data.js`** — regenerated via `node parse.mjs`.
5. **`README.md`** — added Disciplines to the Views table, `disciplines.md` to the directory tree, updated the expected parser output.
6. **`PROMPT.md`** — appended today's prompt.

- **Renderer**: `escapeHtml`, `selectTopic`, `visibleTopics`, `TOPIC_BY_ID`, `.badge.v5/v6/v7` classes — all reused.

### Edge cases handled
- **Missing `disciplines.md`**: parser tolerates ENOENT; view shows a friendly "No disciplines defined" message.
- **Unresolved topic name**: row renders in `.unresolved` faded state with a `?` badge and no click handler; name logged to the parser console with phase context.
- **Duplicate topic across phases**: allowed (no dedupe), each row independent.
- **Filter collapses a column to zero**: column still renders header + "No topics match current filters" placeholder so structure stays visible.
- **Long topic names (e.g. "Calligraphy — Chinese, Japanese, Islamic, and Latin Traditions in Comparison")**: wrap within the middle grid cell without misaligning the number or badge.
- **`&` in topic names**: handled by existing `normalize()` which converts `&` → `and` before lookup.
