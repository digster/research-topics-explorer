# 2026-04-27

## Task: Mark "worked-on" topics with a pastel background across views

### Goal
Let the user mark topics they've worked on from the **Cards** page, and have that marking visually reflect on the **Cards**, **Roadmap**, and **Disciplines** pages via a soft pastel background. Persist marks across sessions (no backend → `localStorage`).

### Suggested color
Soft mint / sage pastel as a low-alpha wash (`rgba(149, 213, 178, 0.14)` for fill, `rgba(149, 213, 178, 0.55)` for the rim accent). Reads as "completed" semantically and composes well over the dark `--bg-elev` without clashing with the v5 (blue) / v6 (purple) / v7 (teal) accent palette.

### Approach
- One `Set<string>` of marked `topic.id`s in the global `STATE` (slug = the join key already shared across all three views).
- Hydrate the `Set` from `localStorage[rte:markedTopics]` on boot; persist as a JSON array on every toggle.
- Single `toggleMarked(id)` mutator → calls `saveMarked()` then `renderCards()` + `renderRoadmap()` + `renderDisciplines()` so all three views stay in sync regardless of which tab is open. DOM is small enough that full re-render is the right tradeoff vs. a pub/sub layer.
- A small ✓ toggle button injected into each Cards-view tile next to the version badge. Click handler uses `stopPropagation()` so the toggle never opens the side panel.
- Read-only mirror in Roadmap and Disciplines (per spec — toggling lives only on the Cards page).
- CSS hooks: `.topic-card.marked`, `.phase-card.marked`, `.discipline-topic.marked` all share the `--marked-bg` fill; the latter two also pick up `--marked-accent` on their borders so the state reads even at a glance.

### Key decisions worth remembering
- **Single re-render on toggle vs. surgical DOM updates** — picked full re-render. ~162 cards, no virtualization, no measurable lag, eliminates a class of "I forgot to re-render view X" bugs.
- **Toggle UI lives only on Cards** — Roadmap and Disciplines are read-only mirrors. Adding the toggle to all three views would dilute the cards page as the canonical "browse + curate" surface.
- **Set in memory + array in localStorage** — `Set` gives O(1) `.has()` per render; JSON array is what `localStorage` can serialize. The serialize/deserialize boundary keeps the hot path clean.
- **Override only `background`, not the shorthand `background-color`** — preserves each view's existing border/accent treatment so the marked state composes additively rather than replacing the whole tile look.
- **Unresolved discipline rows cannot be marked** — they have no stable `topic.id`. Intentional: there's nothing to key off.
- **Toggle is a `<button type="button">` with `aria-pressed` and a meaningful `aria-label`** — accessible by default; the visual ✓ glyph is purely decorative.

### Edge cases / gotchas worth remembering
- **Private mode / localStorage quota** — `saveMarked()` swallows write failures silently so the in-memory state still works for the session. Rehydrate path is best-effort: malformed JSON falls back to `[]`.
- **Filtered-out marked topics** — `visibleTopics()` is applied before render in all three views, so marked topics hidden by sidebar filters correctly stay hidden (no leakage). The mark reappears with the wash when filters are cleared.
- **`renderCards()` re-creates DOM nodes** — any test or external code holding references to a `.topic-card` element across a `toggleMarked()` call will be looking at a detached node. Always re-query after a toggle.
- **Roadmap only renders v5 topics + v6 with `likelyPhase`** — marking a v7 topic intentionally has no roadmap effect because v7 has no roadmap presence. The wash will show up in Cards and Disciplines only for those.
- **Hash-sync (`syncHash`) does not include `markedIds`** — marked state is intentionally session-durable rather than URL-shareable. If sharing a "completed list" via URL ever becomes a goal, that's a separate change.
