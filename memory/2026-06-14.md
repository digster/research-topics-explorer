# 2026-06-14

## Task: resizable sidebars + de-cluttered Knowledge Graph

Two UX reports against the new `index.html` ("The Vault"), with screenshots:
1. Catalog rail discipline labels were clipped (fixed `220px` grid column +
   `text-overflow: ellipsis`) with no way to widen the rail.
2. The Knowledge Graph was unreadable — every node with `r > 7` got an always-on
   11px label with no collision logic (~100 overlapping labels); gentle forces
   (charge −90, link distance 60) packed nodes tightly.

Chosen approach (confirmed via two clarifying questions):
- Graph: **adaptive labels by zoom** (not greedy de-overlap / hover-only).
- Resizer applied to **both** the Catalog and Reader left rails (not Catalog only).

All edits are in the single `index.html`.

### Feature 1 — drag-to-resize rails (Catalog + Reader)
- New `:root` vars `--cat-rail-w: 220px` / `--reader-rail-w: 230px`; the two grids
  gained a **6px `.rail-resizer` track**: `#catalog.active` →
  `var(--cat-rail-w) 6px minmax(0,1fr)`, `#reader.active` →
  `var(--reader-rail-w) 6px minmax(0,1fr) 250px`. The resizer is a thin column with
  a centre hairline that thickens to the terracotta accent on hover/drag.
- One shared helper **`makeRailResizer(handle, container, railEl, cssVar, storageKey)`**
  (next to `loadMarked`/`saveMarked`): restores the saved width up front, writes the
  dragged px into the CSS var (clamped `170 … min(520, container−360)` so the content
  column can't collapse), persists on release to `localStorage` keys
  **`rte:catRailW`** / **`rte:readerRailW`**.
- Wiring: Catalog once at the end of `buildCatalogChrome`; Reader **every render**
  (its chrome is rebuilt by `renderReader`), and the helper re-applies the saved
  width each call, so the width survives phase navigation.
- Bonus: added `title="…"` to each discipline `.lbl` so the full name shows on hover
  even before resizing.

### Feature 2 — adaptive graph labels + looser layout (`renderGraph`)
- Forces loosened: `link.distance` 60→**95** (strength 0.4→0.35), charge −90→
  **size-aware `-140 - d.r*14`**, collide pad +4→**+10** with `.iterations(2)`, plus
  weak `forceX/forceY` (0.03) toward centre so disconnected nodes don't drift into
  tendrils.
- **Per-node `labelMinK`** from an in-degree ranking: top **`BASE_LABELS = 16`** hubs
  get `labelMinK = 0` (always shown); the tail ramps `1.05 → 3.4`. (First tried a
  linear `3.4*(1 - deg/maxDeg)` — with one dominant hub that left only **3** labels
  at base zoom, so I switched to the rank-based scheme for a predictable count.)
- Every node now gets a (truncated) `<text>`, hidden by default in CSS. New
  `applyLabelZoom(k)` in the zoom handler toggles `.show` where `k ≥ labelMinK` and
  sets `font-size = 11/k` so labels stay a **constant ~11px on screen** at any zoom.
  CSS `.node:hover text` and `.node.highlight text` force-reveal individual labels —
  hover/selection handled entirely in CSS, no per-node JS.
- Overlay hint copy: `… · drag · scroll to zoom` → `… · hover for label · zoom in to
  reveal more`.

### Verification (preview @ port 8000, in-browser)
- Catalog: dragging the divider → 360px shows every discipline name in full
  (`stillClippedLabels: []`); min/max clamp to 170 / 520; width persists across
  reload (`360px 6px 1074px`).
- Reader: resizer present in the 4-col grid; drag → 340px persists through a full
  phase re-render (`reader-next`), resizer re-created.
- Graph: 203 nodes / 203 labels created; **16** shown at base zoom (the real hubs:
  Cybernetics, Complex Systems, Network Science, Cognitive Science, …); zoom to k=4
  reveals all 203 at font `2.75` (= 11/4, constant on screen); zoom to k=0.2 → back to
  16 at font `55`. Click hub → 1 highlighted / 183 dimmed / its label `display:block`.
  Toggle v7 off → 203→137 nodes, labels reset to 16; re-toggle → 203. **No console
  errors throughout.**
- Reset my test rail-widths from `localStorage` so the app ships at default widths.

### Tooling note (still true)
`preview_click` on the delegated tab handler was flaky again — eval-dispatched
`MouseEvent('click', {bubbles:true})` on the same buttons fired everything reliably.
Also: synthetic `pointermove` won't satisfy `hasPointerCapture`, which is why the
drag guard keys off the `.dragging` class instead (also more robust in real use).

### Follow-up tweak (same session)
User asked to make the base graph view even cleaner. Lowered `BASE_LABELS`
**16 → 12** and loosened links **distance 95→110, strength 0.35→0.3** to spread the
central hub cluster. Re-verified: **12** labels at base zoom, nodes more spread, no
console errors. (Also had to clear a leftover `STATE.selectedId` from the earlier
click test — it re-highlighted on render and dimmed the graph until Esc + empty
click cleared it.)
