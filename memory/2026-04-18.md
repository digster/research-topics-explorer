## Fix: invisible node labels on the Creators tab

### Problem
On the **Creators** tab, node labels rendered as black text on the near-black dark background (`--bg: #0d0f12`), making topic names like "Philosophy of Mathematics", "Seymour Papert", and "Japanese Aesthetics" unreadable. The force-graph links on the Creators tab were also black and barely visible.

### Root cause
`renderGraph()` (`index.html:731`) is reused by two views — it mounts an SVG into either `#graph` (Graph tab) or `#creators` (Creators tab, via `renderCreators()` at `index.html:1059`). All CSS rules styling the graph were scoped to `#graph` only, so none matched when the SVG lived inside `#creators`. SVG `<text>` and `<line>` elements therefore fell back to the SVG default paint (black) in the Creators view. The `.highlight` / `.dim` state styles also didn't apply on that tab.

### Fix
De-coupled the stylesheet from the container id by moving to a class on the SVG itself:

1. `index.html:750-751` — added `.attr("class", "force-graph")` to the `d3.select(container).append("svg")` chain.
2. `index.html:235-256` — renamed the entire CSS block's selectors from `#graph ...` to `.force-graph ...`, and updated the section comment.

No logic changes. The `.highlight` and `.dim` state classes now work identically on both tabs.

### Why a shared class, not duplicate selectors
`#graph .node text, #creators .node text { ... }` would have worked but is fragile — the moment a third view reuses `renderGraph()`, the bug silently returns. A single `.force-graph` class on the rendered SVG keeps styling tied to the renderer, not to the host container.

### Verification
- Served the worktree locally via `python3 -m http.server` and tested in Playwright.
- **Creators tab:** all labels now render in `--fg-dim` (gray), links visible in `--line-2` (faint gray), matching the Graph tab.
- **Graph tab (regression check):** unchanged — same dim gray labels and links as before.
- **Highlight state:** clicking "Seymour Papert" on the Creators tab produced `computedFill = rgb(227, 231, 238)` (which is `--fg = #e3e7ee`) — i.e. the `.force-graph .node.highlight text { fill: var(--fg) }` rule now correctly applies on the Creators tab. 52 neighbor nodes dimmed as expected.
- Roadmap / Cards / Hubs tabs: unaffected (they don't use `renderGraph()`).
