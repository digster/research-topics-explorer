# 2026-06-10

## Task: fix invisible v8 topics + make the pipeline version-agnostic

### Symptom vs root cause
User reported "parse.mjs can't handle the new v8 CSV entries". The parser was
actually fine — data.js already contained all 192 topics (30 × v8). Two
hardcodes created the illusion and the real breakage:

1. `parse.mjs` `stats.byVersion` + console report only counted v5/v6/v7, so
   `node parse.mjs` printed "162 topics" while writing 192.
2. `index.html` hardcoded `STATE.versions = new Set(["v5","v6","v7"])` (and the
   filter-checkbox list, reset handler, stats bar, legend, badge/bar/phase-card
   CSS, source-file inference) — `isTopicVisible()` filtered v8 out of every
   view with no checkbox to enable it.

A second user concern (roadmap bottom-scrollbar UX) was **withdrawn** during
planning (shift+wheel suffices) — no layout changes were made. User opted to
show v8 on the Roadmap as an overlay like v6.

### What changed

**parse.mjs** (version-agnostic + foolproofing)
- `stats.byVersion` and the console report now derive from actual `version`
  values, naturally sorted (`versionNum()`: "v9" < "v10", non-`v\d+` → last).
- New per-topic `sourceFile` from the CSV `source_file` column (side panel no
  longer infers filename from version — v8 rows correctly say
  `research-topics.csv`).
- Validation: hard-fail listing missing REQUIRED_COLUMNS; non-fatal `⚠`
  warnings for duplicate ids, missing id/name/version, non-numeric phase,
  `connects_to_ids` slots > `connects_to_raw` slots, unknown discipline
  phases (still render, subtitle empty).
- **Import-safe**: exports `parseCSV/csvToRecords/splitPipes/versionNum/
  buildPayload`; `main()` gated on `import.meta.url ===
  pathToFileURL(process.argv[1]).href`. (Fixes the 2026-06-09 footgun where
  importing rewrote data.js.)

**index.html**
- `ALL_VERSIONS`/`VERSION_COUNTS` derived from data; used by STATE init,
  filter checkboxes, reset, stats bar, graph legend, version sort.
- `injectVersionStyles()` at boot generates `.badge.vN`, `.hub-row .bar.vN`,
  `.phase-card.vN` (+ `--accent-vN` golden-angle HSL fallback when not
  hand-picked). Static per-version CSS rules removed. `--accent-v8: #f0a06c`
  (apricot) added. Gotcha: injected sheet comes after the static one, so
  overlay stripe rules use `:not(.marked)` to let `.phase-card.marked` (mint)
  keep winning at equal specificity.
- Roadmap overlay generalized: v6-only → every non-v5 version with a
  `likelyPhase` (first number wins, `^\d+`; out-of-range skipped). Overlay
  cards sorted version-then-name. Removed the redundant `_v` spread-copies.
- Removed dead `colorForVersion()`.

**parse.test.mjs** (new; `node --test parse.test.mjs`, no package.json — kept
dependency-free deliberately)
- 20 tests: CSV grammar; payload transform with synthetic **v9/v10/v12** rows
  (the actual regression class); validation warnings; integration invariants
  on the real CSV with *no hardcoded row counts* (byVersion sums to total,
  ids unique, edges reference known topics, zero warnings) so future versions
  keep it green.

**Docs**: README (192 topics, "Adding a new version" section, tests section,
roadmap overlay description), new ARCHITECTURE.md (data flow + the
"no hardcoded version lists" convention), PROMPT.md appended.
