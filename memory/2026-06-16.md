# 2026-06-16

## Task: "Unselect all" filter button (Catalog rail)

User report (screenshot of the Catalog rail): isolating a single filter is tedious
because you have to uncheck every other box one at a time. Asked for an **Unselect all**
button by the **Reset filters** button. (Planned below it; during planning the user
asked to move it **above** Reset filters.)

All edits are in the single `index.html`.

### The real problem: two clashing filter conventions
The four groups did **not** share semantics:
- `versions` — *literal*: Set held the checked versions; empty = nothing shown; default
  `new Set(ALL_VERSIONS)` (full).
- `disciplines` / `lanes` / `progress` — *overloaded*: default `new Set()` (empty), and
  **empty meant "all"** (the `size > 0` guards in `isTopicVisible`, the `size === 0 ||`
  in `syncCatalogRail`, and the "materialize all on first toggle" line in each change
  handler).

So a naive "set everything empty" would have left discipline/lane/progress boxes
rendering as **checked** (empty = all-checked). That asymmetry is why this wasn't a
one-line add.

### Misstep caught by verification (worth remembering)
First implementation unified everything onto **strict literal AND** (dropped all
`size > 0` guards; empty = nothing). In-browser test of "Unselect all → check only
*Design & Making*" returned **0 cards**, not 32 — because the now-empty `versions` /
`lanes` / `progress` groups matched nothing, so the discipline pick was AND-ed away.
That makes the feature *worse* than the manual unchecking it was meant to replace. The
approved plan was internally inconsistent here (its step 3 expected "only that
discipline appears", which literal-AND can't deliver).

### Final model — faceted filtering (shipped)
Each `STATE` Set holds exactly the checked boxes; an **empty group = "no constraint"**
(that facet shows all). One consistent rule across all four groups:
- `isTopicVisible`: `if (STATE.X.size > 0 && !STATE.X.has(...)) return false;` for every
  group (extended the old discipline/lane/progress pattern to `versions` too).
- `syncCatalogRail`: literal `i.checked = STATE.X.has(...)` for every group (extended the
  old `versions` rendering to the others; dropped `size === 0 ||`).
- Change handlers: just `add`/`delete` (removed the "materialize all on empty" lines —
  no longer needed, since the full-checked state is now a full Set, not empty).
- Defaults (`STATE`): all four are **full** Sets (`versions` = `ALL_VERSIONS`,
  `disciplines` = `DISCIPLINES.map(d=>d.phase)`, `lanes` = `LANES`,
  `progress` = `["toread","done"]`) → load looks all-checked, shows all 203.
- **Reset filters** (`#cat-reset`): restore the full Sets + clear search.
- **Unselect all** (`#cat-unselect`, new button above Reset, reuses `.reset-btn`): empty
  all four Sets; **search text left intact** (it's not a checkbox). Empty = no constraint,
  so the full catalog stays visible — a clean slate to check the one facet you want.

Net effect: isolating a single filter is now one click (Unselect all → check one box),
and the code lost three special-cases (handlers + sync + visibility all simpler).

Only cross-view consumer of these Sets is the graph legend version chips
(`index.html` ~1102/1111) — `versions` was already literal there, so no change needed.

### Verification (preview @ port 8000, in-browser)
- Default: 5/5 ver, 10/10 disc, 5/5 lane, 2/2 prog checked, `showing 203 of 203`.
- Type "theory" → 86 shown, facets untouched.
- **Unselect all** → every group `0/N` checked, search still "theory", still 86 (empty =
  no constraint, not zero).
- Clear search + check only *Design & Making* (`data-disc=6`) → `showing 32 of 203`,
  `distinctDisciplines: ["Design & Making"]`, other groups still 0/N. ✓ the goal.
- **Reset filters** → all re-checked, 203, search cleared.
- Knowledge Graph: toggle v5 chip off → circles 406 → 294 (V5 = 56 topics × 2 circles),
  version filter still drives the graph.
- No console errors/warnings throughout.
