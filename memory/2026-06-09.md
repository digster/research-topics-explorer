# 2026-06-09

## Task: CSV superset database of the three research-topics MD files

### Goal
Create a single CSV file whose schema is a superset of the topic-level data in
`research-topics-v5.md` / `-v6.md` / `-v7.md`, to serve as the database for the
research topics exploration going forward. Constraint: change nothing else in
the repo. User decisions (via AskUserQuestion): fold in the `disciplines.md`
phase mapping as columns; topics only (no "Deliberate Omissions" rows); deliver
the **CSV only** — extraction ran once via a throwaway script outside the repo
(`/tmp/md-to-csv.mjs`, since deleted), no committed migration script.

### Deliverable
**`research-topics.csv`** at repo root — 162 data rows (v5=56, v6=35, v7=71)
× 21 columns, RFC 4180 (quoted fields keep real newlines; multi-value cells are
pipe-separated because values contain commas).

### Schema (one row per topic)
`id, version, id_code, name, group_code, group_label, tier, phase, likely_phase,
phase_rationale, key_figures, primary_source, one_line_pitch, description,
connects_to_raw, connects_to_ids, master_table_connections, discipline_phase,
discipline_name, source_file, source_date`

- `id` = same slug algorithm as `parse.mjs` `slugify()` → identical to data.js
  ids / URL hashes / `rte:markedTopics` localStorage keys.
- `connects_to_ids` is **positionally aligned** with `connects_to_raw`
  (unresolved → empty slot, e.g. `a||c`), resolved with parse.mjs's
  `resolveConnection` + alias table, so resolution is now curated data.
- Superset additions over data.js: v5 per-phase **"Why Here"** rationale
  (`phase_rationale`), master-table **"Primary Connections"**
  (`master_table_connections`), v7 **"Primary Source"** column, v5 master rank
  as `id_code`, and the disciplines overlay as two columns.
- Intentionally excluded: `inDegree`/`outDegree` (derivable), omissions tables,
  document-level prose. `tier` is empty for v7 (groups are not tiers).

### Key findings worth remembering
- **parse.mjs's 3-token-prefix fallback misses 5 master-table rows** whose
  names are abbreviated or word-reordered vs the `###` headings: v6 "Memory &
  Mnemonic Systems" (A5), "Knowledge Graphs & Semantic Web" (A8), "Attention
  Economy & Attention Studies" (C5, word-reordered), "Reservoir & Neuromorphic
  Computation" (C12), and v7 "Calligraphy — 4 traditions in comparison" (C5).
  In data.js those 5 topics have `idCode: null` (and null `likelyPhase`/`pitch`).
  The CSV extractor added a stage-3 **token-set containment fallback**
  (stopwords + numerics dropped, ≥0.75 overlap of the smaller set, all 6 hits
  scored 1.00) — applied to metadata lookups only, never to connection
  resolution, so id/edge parity with data.js is preserved.
- The CSV fills **66 metadata gaps** vs data.js: 56 v5 `id_code`s + the
  10 fields belonging to those 5 topics.
- Importing parse.mjs is unsafe for tooling — it executes `main()` on import
  and rewrites data.js. Helpers must be copied.
