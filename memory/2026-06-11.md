# 2026-06-11

## Task: UI ideation for better topic exploration (mockups only — NO app changes)

User asked for better UI ideas to explore the topics, explicitly "don't change
anything yet, just show me visually". Four mockups were rendered in chat
(built from real data.js rows — Information Theory in/out edges, FEP v8
bridge, the 10 discipline names). Only PROMPT.md and this memory file were
touched; index.html / parse.mjs / data.js / CSV untouched.

### Ideas presented (in recommended order)

1. **Focus trail (Miller-column ego browser)** — recommended first build.
   Breadcrumb trail of visited topics + 3 columns: incoming connections |
   current topic card | outgoing connections. Rationale: ego view complexity
   is bounded by node degree (~7–18) instead of all 192 nodes/760 edges;
   incoming edges are currently invisible in the app (side panel shows only
   outgoing chips) even though the reverse index is trivial from curated
   `connects_to_ids` and `inDegree` is already computed. Unresolved
   connections keep their faded-chip treatment.

2. **"What's next" frontier dashboard** — recommended second build.
   Uses `localStorage["rte:markedTopics"]` (today only a mint wash) as a
   recommender: rank unmarked topics by |connections ∩ marked set|, show
   "via X, Y, +n" provenance chips, plus metric cards (worked-on count,
   frontier size, densest next phase). Zero new data needed; one
   set-intersection pass at boot.

3. **Metro-map roadmap** — phases on x-axis (as today), disciplines
   (`discipline_phase`/`discipline_name`, 10 lines) as colored metro lines,
   topics as stations, multi-line capsule = interchange (fits v8
   "High-Leverage Bridges" semantics; FEP "3 or 7" mocked at phase 3).
   Filled station = marked. Most layout work of the four (station collision
   avoidance); SVG, d3 already loaded.

4. **Discipline adjacency matrix** — aggregate the 760 directed edges into a
   10×10 discipline→discipline heat grid; click a cell to list the topic
   pairs in the existing side panel. Surfaces dense bridges and gap deserts
   the force graph hides. Plain DOM grid, one aggregation pass.

Honorable mentions (prose only, no mockups): Cmd+K command palette with
fuzzy jump + recent-trail history; radial hierarchical edge bundling as a
Graph-view alternative; a "serendipity" random-walk button.

### Feasibility notes (all fit the no-build vanilla-JS constraint)
- Ideas 1, 2, 4 are plain DOM + existing payload fields; no parse.mjs or CSV
  changes required. Idea 3 is SVG; disciplines give the line assignment.
- Any build must stay version-agnostic per ARCHITECTURE.md (derive from
  ALL_VERSIONS, no hardcoded version lists) and respect the topic-id
  contract (URL hashes + rte:markedTopics).
