### The gotcha worth remembering (→ new `LEARNINGS.md`)
The CSV has a **CRLF header** but LF-terminated records. Splitting the header
on `,` gave a final column named `"source_date\r"`, so a row object keyed by
the clean name didn't match. Caught only because the append script asserted
"header column set == row key set" before serializing.

**This would not have been caught downstream**: `parse.mjs` strips `\r` in its
character loop, so a misaligned row parses *cleanly* and emits a wrong
`data.js` with **zero warnings**. Appended with `\n` to match the surrounding
records and keep the diff a one-line addition.

Created `LEARNINGS.md` (didn't exist) documenting this plus: CSV edits are
always a two-file change; `connects_to_*` positional alignment (a *shorter*
ids list fails silently); per-cohort field dialects; a version tag is a UI
facet; shared filter state spans all views.

## Follow-up: reciprocal links (same session)

> Reciprocal links should always be updated when required.

Standing curation rule, not a one-off. Applied it to the 10 rows Critical
Theory links out to.

### Why it wasn't automatic
Nothing in the pipeline infers reciprocity: the detail panel renders *Outgoing*
and *Incoming* as separate lists, and the graph's `labelMinK` hub ranking is
**in-degree**-based. So a topic with 10 out / 0 in can never rank as a hub no
matter how central it is conceptually.

Context worth keeping: the dataset was only **19% reciprocated** before this
(160 of 844 directed edges). One-way links were the norm — historical curation
debt rather than deliberate asymmetry. Now 21.1% (180/854).

### How the edit was made (repeatable)
Surgical, not a full re-serialization: for each target row, compute its exact
serialized `connects_to_raw,connects_to_ids` pair, **assert it occurs exactly
once** in the file text, and swap in the extended version. Re-serializing all
204 rows would normalize quoting and line endings everywhere and bury the real
change.

Defensive step that mattered conceptually even though it was a no-op here: pad
`connects_to_ids` with empty slots up to `connects_to_raw`'s length **before**
appending. All 10 targets happened to be aligned, but on a row with trailing
unresolved slots the new id would otherwise pair with an earlier raw label and
silently mislabel the edge.

Also hit a triviality worth noting: a scratchpad script importing `./parse.mjs`
resolves relative to the *script*, not the cwd — needed the absolute project
path.

### Verification
- Diffed against `git show HEAD:research-topics.csv`: exactly **10 rows**
  changed, **only** in `connects_to_raw` / `connects_to_ids`, every
  pre-existing slot pairing byte-identical, back-link appended last in both
  columns. No other field on any row moved.
- `node parse.mjs` → 204 topics, **854 edges** (844 + 10), 263 unresolved
  (unchanged), **zero warnings**. Tests **20/20**.
- In-browser: panel reads **`in 10 · out 10`** with both *Outgoing — connects
  to (10)* and *Incoming — referenced by (10)* populated; all 10 out/in pairs
  mutual. Spot-checked two modified rows (Foucault `out 5→6`, Epistemology
  `out 5→6`) — new chip renders last and correctly labelled. *History &
  Philosophy of Science* card ticked 15 → 16 links. No console errors.

## Follow-up 2: symmetric closure of the whole graph

> Okay, work on the one way edges.

### Decision taken first (two clarifying questions)
Measured the blast radius before editing and surfaced that full reciprocation
is **not just a data change** — three UI affordances are built on connections
being directed:

| Surface | After reciprocation |
|---|---|
| Detail panel | *Outgoing (N)* / *Incoming (N)* become identical lists |
| `in N · out N` badge | always the same N twice |
| Hubs view | In-degree and Out-degree tabs rank identically |
| Knowledge Graph | every edge drawn twice; `forceLink` pulls twice per pair |

Asked (a) full vs selective vs render-time symmetry, and (b) whether to
simplify the direction-based UI — since that removes existing functionality.
User chose **full reciprocation in the CSV** + **simplify the UI to match**.

Reassuring pre-check: the hub ranking barely moves (**10 of 12** base labels
unchanged), and only 3 rows exceed 30 connections, so the graph's character
survives.

### Data
666 back-links across **115 of 204 rows**; 854 → **1520** directed edges;
**0 one-way edges** remain. Same surgical technique as the 10-row pass (locate
each row's exact serialized `connects_to_raw,connects_to_ids` pair, assert a
single match, swap), after first confirming all 204 connection-pair
serializations are unique so the anchoring is safe.

Verified against HEAD: **only** the two connection columns changed on those
115 rows, every pre-existing slot pairing survived in place, raw/ids lengths
stayed equal, no other field on any row moved.

### The subtlety that shaped the code: degrees count slots, not targets
After the closure, 17 topics still showed `inDegree !== outDegree`. Cause:
`parse.mjs` counts **slots**, and **12 rows name one topic through two raw
labels** — "AI" *and* "machine learning" both resolving to Machine Learning,
"Complex systems" *and* "chaos theory" both to Complex Systems. That is one
relationship with two authored phrasings.

Deliberately **kept** those duplicate raw labels in the CSV (they preserve the
author's voice) and deduped **by target** in the app instead.

### Code (all in `index.html`)
- **`NEIGHBOURS` / `DEGREE`** computed at boot — distinct neighbours per topic.
  Needed because `inDegree + outDegree` now double-counts *and* slot counts
  over-count the duplicate-label rows. Every view that ranks or sizes by
  connectedness reads it (Catalog "N links" + "most connected" sort, graph node
  radius, label ranking), so they can't drift apart. Hubs is the deliberate
  exception — it honours the version filter, so it recomputes against the
  visible set.
- **Panel**: one deduped `Connects to (N)` list (unresolved slots still trail
  as faded chips); badge → `N connections`. Also removed the `incoming`
  `TOPICS.filter(...)` scan — an O(n²) pass on every panel render.
- **Hubs**: In-degree + Out-degree tabs merged into **Connections**; Bridge
  score kept and switched to distinct visible neighbours. Default `hubsMode`
  → `"connections"` (in-memory only, so no migration needed).
- **Graph**: `renderGraph` collapses EDGES to one line per unordered pair.
  Without it every relationship draws twice (stacked strokes read heavier) and
  `forceLink` applies its pull per copy, contracting the layout deliberately
  loosened in June. **1520 edges → 754 lines** — *fewer* line elements than the
  854 before, so the graph came out cleaner, not denser.
- Legend hint `node size = in-degree` → `node size = connections`.

### 754, not 760
`edges.length / 2` = 760, but 12 of the 1520 directed edges are duplicate-label
repeats of an existing pair: (1520 − 12) / 2 = **754**. The dedup absorbs both
the symmetry and the duplicate labels.

## Follow-up 3: symmetry regression test

> Okay, add the first test.

Added **`integration: every connection in the real CSV is mutual`** to
`parse.test.mjs`. Suite now **21/21**.

### Why this one was worth it
The symmetry invariant had **nothing enforcing it**. A hand-added one-way row
is valid CSV and produces a warning-free `data.js`, so `parse.mjs` cannot catch
it — but it breaks the detail panel's single "Connects to" list, the Hubs
"Connections" ranking, and the graph's degree-based sizing, all of which now
assume mutual edges.

### Design choices
- **Integration section, not synthetic.** Several synthetic fixtures (e.g.
  "edges resolve across versions") are deliberately one-way, so a global
  assertion would have broken them. The invariant is a property of the curated
  CSV, not of `buildPayload`.
- **Neighbour Sets, not edge counts.** Folding `payload.edges` into per-topic
  Sets makes the 12 duplicate-raw-label rows ("AI" + "machine learning" → one
  target) collapse naturally, so they can't read as a violation.
- **Names offenders, doesn't just count.** The fix is always identical, so the
  message prints each pair plus the exact columns to append to, caps the list
  at 10 with "…and N more", and points at LEARNINGS.

### Verified the failure path, not just the pass
A test that has only ever passed proves nothing. Backed up the CSV, then:
- deleted **one** back-link → fails, naming that exact pair and fix;
- deleted **all 10** to Critical Theory → "10 one-way connection(s)", all listed;
- deleted **all 34** to Machine Learning → "34 …" + "…and 24 more" (truncation
  branch).
Restored byte-identically from the backup after each (confirmed by comparison,
**not** `git checkout` — that would have wiped the 666 back-links before they
were committed). Also reverted a `data.js` regeneration whose only diff was the
`generatedAt` timestamp, keeping the commit single-purpose.

First wording of the failure ("X is listed by nobody in Y") read backwards;
rewrote as "X -> Y, which does not link back" + an indented `fix:` line.
