## Task: light-editorial "Research Vault" redesign in a new index.html

User attached 4 wireframes from Claude Design and asked to rename the current app
to `index.v0.html` and rebuild the new design from the ground up in a fresh
`index.html` — wireframes as **reference, not copy**; keep the worked-on toggle;
show the design for approval first.

### Scope clarified during planning (3 rounds of questions/corrections)
- **Theme**: unify the wireframes' three clashing looks (dark constellation /
  cream reader / hand-drawn paper) into ONE — chosen **light editorial vault**
  (warm paper, serif display, terracotta accent, one colour per discipline; the
  graph is the only dark-canvas view).
- **Views**: build only the **four with screenshots** — Knowledge Graph, Catalog,
  Thinkers, Reader — **plus Hubs** carried over from v0 (user asked for it). **5
  total.** Phase Path + Priority Board were in the wireframe tab bar but never
  designed → **out of scope** (user's "four new views" = the 4 screenshots).
- **Progress model**: keep the **binary** worked-on toggle (preserve
  `rte:markedTopics`), surfaced as "Done" — NOT the 3-state To read/Reading/Done
  shown in the Catalog screenshot.
- **Version filter** (v5–v9) must be present where it applies (user flagged it
  missing from the first plan).

### What I did
- `git mv index.html index.v0.html` — old six-view app kept verbatim, still
  runnable, reads the same `data.js`. (Hubs + Creators live on there.)
- Wrote a brand-new **`index.html`** ("The Vault"): single file, no framework,
  d3@7 + marked@13 from jsdelivr, same as v0. **No data-pipeline edits** —
  re-presents `window.RESEARCH_DATA` through three boot-derived lenses:
  - `DISCIPLINE_OF` (topic.id → {phase,name,color}) from `DATA.disciplines`; 10
    hand-picked discipline accent colours are the **primary** visual encoding.
  - `laneOf()`/`LANE_OF` priority lane from `groupLabel` keywords (Catalog filter
    only — no Priority Board view).
  - `buildThinkerIndex()` aggregates `keyFigures` over *visible* topics (~898
    people; 50 thread through 2+ topics).
- Five views: **Catalog** (default; rail filters Version/Discipline/Lane/Progress
  + sorts by discipline/most-connected/A–Z), **Knowledge Graph** (dark canvas,
  nodes coloured by discipline, legend doubles as version filter), **Thinkers**
  (featured threaders + search-reveals-everyone, "profile" link to a creator
  node), **Reader** (one-discipline reading layout: path rail + topics + up next),
  **Hubs** (in/out/bridge, reused from v0; bridge now spans version OR discipline).
- Preserved: binary worked-on toggle (`rte:markedTopics`, mirrored on Reader rows
  + header "X done · total" meter), shared `isTopicVisible()`/`visibleTopics()`
  filtering across all views, slide-over detail panel (Esc/✕ to close),
  `#view=…&topic=…` deep-linking.
- Docs: README (intro + Views table + worked-on + tree + deep-link example),
  ARCHITECTURE (new "presentation layer" section + v0 retained + marked note),
  PROMPT, this memory.

### UX detail worth remembering
Searchable views (Catalog, Thinkers) build their chrome **once** (guarded by a
`root.dataset.built` flag) and only re-render the results container on
filter/search changes — otherwise re-rendering the `<input>` on every keystroke
kills the caret. Same separation v0 got "for free" by keeping search in a static
sidebar. The shared version filter is editable from the Catalog rail AND the
graph legend chips; `syncCatalogRail()` reflects STATE back into the rail
checkboxes so a graph-side toggle shows up when you return to Catalog.

## Follow-up: filter non-name tokens out of the Thinkers view

User noticed Thinkers surfaced `1980` as a "person". Investigated: `key_figures`
is a free-text column reused across node types, so it also holds publication
years, concept terms, and quoted titles. Counts (898 unique strings):
**104 clearly-non-name and auto-detectable** — 10 pure years, 12 with a digit,
12 quoted phrases/titles, 70 all-lowercase concept terms — plus an unknown
~40–80 capitalised book/institution titles that can't be told from names without
a curated list. Only **2** of the non-names were "threaders" (2+ topics, so shown
by default): `the rhizome (2)` and `1980 (2)`.

Applied a display-time `looksLikePerson()` filter inside `buildThinkerIndex()`
(rejects digit / leading-quote / all-lowercase). **Thinkers-only** — Catalog
cards and the detail panel still show `key_figures` verbatim. Verified: headline
898 → **794**, featured 50 → **48**, both noise cards gone, `affordances`/`1980`
searches now return 0, while `shannon`/`lakoff` still resolve. The capitalised
titles intentionally remain (the documented tradeoff for zero false positives).
